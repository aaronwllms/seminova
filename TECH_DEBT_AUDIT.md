## Executive summary

- **Auth-boundary enforcement gaps are closed (F187, S012).** The matcher now permits Next.js route-group hash suffixes on metadata images (5–6 base-36 chars at the image position only); `/auth/**` is a real path segment; the public-route predicate is exported and pinned against discovery; metadata-image files are location-checked. Residual: ≤4-character hash suffixes stay gated (~0.04% of route groups) — marked with a `// debt:` comment in `proxy-matcher.ts`.
- **Dependency findings all closed.** `next` was upgraded 16.2.9 → 16.3.3 (F101) and the stale override pins were refreshed (F102), taking `pnpm audit` from 20 vulnerabilities to zero. F081's `sharp` override was removed in the same commit as F102, its blocker cleared by the upgrade. Note both version targets recorded at this pass turned out stale or wrong — see § Resolved for the Active-LTS and capped-range lessons.
- **Three correctness bugs with user-visible or security consequences.** The client-log relay lets an unauthenticated caller forge the `userId` on a persisted log row, contradicting the guarantee ADR-0007 states in prose (F103). The proxy's redirect helper copies auth cookies by name and value only, dropping `HttpOnly`, `Secure`, `SameSite`, and expiry (F104) — and coverage confirms those two lines are untested. The admin users list infers "has next page" from a full page, so 15 users at the default page size shows an enabled Next button leading to an empty page (F107).
- **Three reopen triggers fired since the last pass.** F061 (duplicate profile dialog providers) now has four mount sites, not the two its marker warned about. F089 (next-themes hydration guards) now has three identical copies, which was the stated threshold. F060 resolved itself in the other direction — the second copy of the shared grid track dissolved in Phase 19, leaving only a stale comment (F139).
- **The enforcement layer has a hole in it.** `eslint-rules/semantic-tokens.mjs` is the sole mechanical enforcement of a documented hard constraint and has zero tests (F108); the root cause is that vitest coverage `include` is `src/**` only, so ~570 LOC of custom lint rules and check scripts sit outside the 80% thresholds entirely (F122). Relatedly, the previous audit's "no circular dependencies" tooling note was a **false negative** — `madge` was invoked without `--ts-config`, so it resolved none of the `@/` aliases; with paths resolved there is one genuine value-carrying cycle (F109, F110).
- **Admin surface layering inverted.** The group-wide admin authorization contract (`assertAdminCaller`, the error envelope type) lives inside the *users* surface; logs aliases it through a shim, settings imports it directly, and the group-level `admin/_lib/` helper imports upward from a surface folder (F105).
- **Server-side authorization itself is sound.** Every privileged admin action gates independently rather than trusting the proxy; self-target guards are enforced server-side; the secret-key client is unreachable from the browser; all three tables have per-operation RLS; every `SECURITY DEFINER` function pins `search_path`. See § Verified OK.
- **Quality gates are green** — `type-check`, `lint`, and `test:ci` all pass; 780 tests / 152 files; coverage thresholds met. The gates are not what is failing here; the gaps are in what the gates cover.
- **Five declared `// debt:` markers need attention as markers**, independent of their subject: one is stale because its trigger already fired and the upgrade shipped (F141), one has wording whose literal condition now reads as satisfied when it isn't (F142), and one names a triplication that is currently true (F143).
- **Volume caveat:** this pass produced 79 findings against a 30–80 target. That is the cost of 13 months of phase work with only sync passes in between, not a sudden collapse in quality — 44 of the 79 are Low severity and most are single-file, S-effort.

## Architectural mental model

Seminova is a **Next.js 16 App Router template** organized by route group: public `(marketing)/`, `auth/`, authenticated `(app)/` at `/home`, and `admin/` at `/admin/**`. Session gating runs in `src/proxy.ts` → `src/supabase/proxy.ts` — the single highest-churn source file in the repo at 21 commits in six months. The **two-authority refresh model** (proxy on matched server requests plus browser foreground auto-refresh) per ADR-0005 is what makes Supabase Realtime viable on `/admin/logs`.

Data access splits three ways: a browser client under RLS, a server session client, and a secret-key service client reserved for admin user mutations, log persistence, and first-password setup. The **admin surface is the complexity center** — three sibling surfaces (users, logs, settings) that solve overlapping problems (pagination, filter chips, refresh indication, save orchestration) and have drifted apart from each other in the details. Phase 14 extracted the shared helpers that were obviously shared; what remains is the harder class, where two surfaces solve the same problem *differently* and one of them is wrong (F107, F118, F130).

A second, quieter axis of the architecture is the **enforcement layer**: nine hard constraints, each backed by a check script or custom ESLint rule, wired into both `pre-push` and CI. This layer is load-bearing for the template's value proposition — a spinoff inherits the guardrails, not just the code. It is also the least-tested part of the repo (F108, F116, F122), and this pass found two checkers weaker than the contract they appear to serve (F120, F121).

**Hot paths:** `src/proxy.ts` (every matched request), `require-auth.ts`, the two admin table-state hooks and their TanStack Query layers, `persistAppLogRow`, profile blur-save, avatar upload.

**Cold corners:** strict nonce-based `script-src` (F053, externally blocked), MSW infrastructure (F072, accepted), rate limiting on `/api/client-logs` (F082).

**Largest source files (LOC, non-test):** `banner-setting-row.tsx` (492), `workflow-diagram.tsx` (486), `use-admin-users-table-state.ts` (385), `use-admin-logs-table-state.ts` (375), `profile/actions.ts` (352), `a11y-structure.mjs` (350), `reference-profile-settings-preview.tsx` (346), `features-content.ts` (332). All re-verified against ADR-0001; the first four are legitimate deep modules (see § Verified OK).

**Git churn (6 months):** `supabase/proxy.ts` (21), `logs-table.tsx` (19), `login-form.tsx` (18), `users-table.tsx` (18), `sign-up-form.tsx` (16), `config/site.ts` (14), `workflow-diagram.tsx` (14). The intersection of churn and missing tests is the auth-form family and the admin table state hooks — which is where F107, F114, F130, and F133 landed.

## Top 5

1. **F103 — Strip the caller-supplied `userId` before merging relay context.** One line, plus a test. Right now the merge only overwrites `userId` when a session exists, so on the unauthenticated path — the case ADR-0007 is written for — a caller controls the field the ADR calls out as the only non-claim in the row. That makes every attributed row in `app_logs` untrustworthy, which quietly undermines the observability surface the admin logs page is built on. Fix the code, not the ADR: ADRs in this repo are immutable history, and the ADR's stated intent is the stronger, correct guarantee.

2. **F104 + F107 — Two small bugs in high-churn paths that tests should have caught.** The proxy's redirect helper drops `HttpOnly`, `Secure`, `SameSite`, and expiry from auth cookies, and coverage shows those two lines are the file's only uncovered branch — in the repo's single highest-churn source file. 4. **F106 — Make the admin mutation result a real discriminated union.** `Exclude<string, 'not_found'>` is a silent no-op: `Exclude` distributes only over unions, and `string` is not one, so the type collapses to plain `string` and `TStatus` infers as `string` for every caller. ## Verified OK

Areas that look alarming but are sound. Not a substitute for § Accepted.

- **Server-side admin authorization.** Every privileged action independently calls `assertAdminCaller` before touching data — the proxy is never treated as sufficient. Verified across all list, stats, tags, mark-read, and mutation actions. `assertAdminCaller` itself reads `app_metadata.role` via `getUser()` (a verified server call, not a client claim), fails closed on error, and never consults `profiles`. F105 is about where this code *lives*, not whether it works.
- **Self-target guards.** Ban and demote both reject the caller acting on their own account inside the action, not just in the UI.
- **Secret-key containment.** `createServiceClient` is reachable only from `run-admin-user-mutation.ts`, which is not a client module and is not exported through any client-reachable barrel. The ESLint default-deny with an explicit server allowlist backs this mechanically.
- **ILIKE injection.** The logs search escapes backslash, `%`, and `_`, then wraps values containing commas or parens for PostgREST. Correct and non-obvious.
- **Realtime cleanup and scoping.** The logs channel is removed and the debounce timer cleared on both the disabled branch and unmount. Logs subscribes to INSERT only; users uses focus-refetch with no subscription — matching ADR-0008 exactly.
- **RLS and SQL hygiene.** All three custom tables have RLS with per-operation policies, `(select auth.uid())` wrapping, and no `for all`. Every `SECURITY DEFINER` function pins `search_path`. Column-level `grant update` on `profiles` restricts clients to display name, avatar, and bio, so `has_password` cannot be self-set. The five migrations redefining `admin_list_users` in full are how immutable migration history works, not copy-paste duplication.
- **Deep modules, re-verified against ADR-0001.** `banner-setting-row.tsx` at 492 LOC (grown from 429 via Phase 18 persistence/dismissal, all serving one responsibility: edit one banner setting; four props, one real export, no co-change with siblings). `workflow-diagram.tsx` at 486 (one responsibility, one-prop interface, length is SVG coordinate markup). `use-admin-users-table-state.ts` (385) and `use-admin-logs-table-state.ts` (375) — wide *return* shapes, but each is a private channel to a single consumer, not a public API. `src/supabase/proxy.ts` at 189 (one responsibility behind one exported function, with Supabase-mandated ordering comments explaining why the internals cannot be split). `profile/actions.ts` at 352 (three server actions on one surface, length is repeated error-envelope literals, not tangled concerns).
- **Vendored shadcn surface.** knip's unused-export list is dominated by `src/components/ui/sidebar/**`, `table.tsx`, `tabs.tsx`, `toggle.tsx`, and `dropdown-menu.tsx`. This is the primitive-first hard constraint working as designed — composition surface area, not dead product code.
- **Dev-only `'unsafe-eval'` in the CSP.** `next.config.ts` evaluates `headers()` at build time, so the development branch cannot reach a production response. Correctly gated; only the audit prose describing it is stale (F166).
- **`src/supabase/server.ts` swallowing cookie-write errors.** Required by the RSC model and documented in the file header; the proxy is the writing authority.
- **`isSafeRedirect` and `isSafeUrlScheme` as two separate utilities.** Genuinely different threat models — same-origin `next` validation versus a render-time scheme check on DB-sourced URLs — and each file says so.
- **`getCurrentUserProfile` failing closed to `hasPassword: true`.** Looks like a wrong default; it is the deliberate fail-closed guard ADR-0012 requires so a failed profile load never exposes the no-reauth form.
- **`dangerouslySetInnerHTML` on the landing page.** The single sanctioned exception in `seo.mdc`; the JSON-LD is unicode-escaped by its builder before it arrives.
- **Env var discipline.** `env.ts` is the single reader of the Supabase vars and `site-url.ts` the single reader of the site-URL vars. Every `process.env` reference cross-checks against `.env.example` and README with no undocumented or unused variable.
- **`useToggleFilterSet` returning a memoized object.** Looks like speculative memoization; the object is consumed by downstream effect dependency arrays, so the stable identity is load-bearing.
- **`stat-tile.tsx` sr-only span alongside a Radix tooltip.** Looks like the mixed-ARIA-relationship antipattern; Radix removes tooltip content from the DOM when closed, so the span is the standard workaround, and three tests pin it.
- **Coverage exclusions for `page.tsx` / `layout.tsx` / `src/components/ui/**` / reference demo shells / static workflow sections.** Thin shells, vendored primitives, or static marketing prose. The interactive `workflow-diagram.tsx` is measured. Note the reference exclusion is why F152's parity drift went unnoticed — the exclusion is defensible, the unverified parity *claim* is the finding.
- **No `src/services/` layer.** Two tables plus RPCs; premature per `code-minimalism.mdc`.
- **Dual admin gating (proxy + `AdminAuthGate`).** Defense-in-depth; `AdminAuthGate` probes `hasServerAuthSession` before reading claims on a cold cache. Keep both.
- **Zero `any`, `as any`, `as unknown as`, or `@ts-ignore` in production code; zero raw hex or numeric Tailwind color scales anywhere in `src/`; zero raw `console.*` outside the documented exempt surfaces.** The type and token discipline genuinely holds — the type findings in this audit are all about assertions and unsound generics, not escape hatches.

## Open questions

- **F147 (StatTile `unread` variant)** — should the Unread stat tile be primary-tinted? The variant exists and is never used; the tile that should use it passes `role="total"`. This is a product/design call, not a code call.
- **F161 (`noUncheckedIndexedAccess`)** — repo-wide strictness change with a one-time fix cost across a handful of sites. My recommendation is yes; it needs your approval because it changes the compiler contract for all future work.
- **F170 (admin-layout revalidation)** — is the `/admin` revalidation after a password flag stamp load-bearing for any admin surface, or leftover? I could not find a consumer. The recovery/first-password divergence is closed.
- **F182 (`@shadcnblocks` registry)** — keep the configured-but-unused registry and document the review expectation, or remove it? Either is defensible; leaving it undocumented is the only bad option.
- **`AdminAuthGate` indefinite skeleton** — for an authenticated-but-not-yet-established session the gate renders a skeleton rather than redirecting. Is that a deliberate choice to avoid a redirect loop against the proxy, and is there a path where a user sits on it indefinitely instead of being sent to login?
- **`syncAdminSettingsVisitKey` mutating module state during render** — it is idempotent per pathname so StrictMode double-render is safe, but the doc comment claims it is "safe to call from any admin shell render," which an impure render-phase function cannot guarantee under concurrent rendering. Was an effect-based or router-event-based approach considered and rejected, or does the accordion-collapse-on-revisit behavior specifically need the value during first render?
- **`toJsonSafeContext` in `persist-app-log.ts`** — it performs a JSON round-trip, discards the result, and returns the original value, so it works as a serializability probe but does not sanitize. Was returning the un-normalized value intentional (letting Supabase serialize), or was the intent to return the round-tripped clone so nested `Error` and `Date` values normalize before insert?
- **Test placement convention across admin surfaces** — logs tests its server actions at the barrel (`logs/actions.unit.test.ts`, 451 LOC covering both `_lib` action modules) while users tests at the module (`users/_lib/list-actions.unit.test.ts`). Coverage is comparable either way. Is one the intended convention worth stating in `testing.mdc`, or is placement deliberately left to the author?
- **`cliLog` vs `appLog` threshold caching** — `cliLog` caches the log-level threshold for the process lifetime while `appLog` re-resolves per call. Fine for short-lived CLI processes, but is the divergence deliberate or incidental?
- **`(app)/layout.tsx` passing `children` to both the Suspense fallback and the resolved shell** — does the page subtree render twice per request while the banner resolves, or does React Flight's reference deduplication make it free? If it renders twice, any page-level fetch not wrapped in `cache()` runs twice.
