# Tech Debt Audit — Seminova

Generated: 2026-07-02

## Executive summary

- **Starter demo scaffolding still ships in production paths:** `useGetMessage` + `axios` + MSW `/api/message` handler reference a route that does not exist; nothing in the app imports the hook.
- **Dead template artifacts accumulate:** `auth-button.tsx`, `providers/ThemeProvider.tsx`, `landing-copyright.tsx`, and unused shadcn primitives (`checkbox`, `collapsible`) are orphaned; `LogoutButton` is only reachable through dead `AuthButton`.
- **React Query Devtools ship in the root layout unconditionally** — extra client bundle and UI chrome in production.
- **Declared CSP debt is real:** report-only CSP cannot be enforced without a nonce strategy (`security-headers.ts` `// debt:` marker).
- **Admin users list uses two different Auth Admin API call styles** (SDK `listUsers` vs raw `fetch` with secret key) depending on search — workable but brittle and hard to test uniformly.
- **Coverage gates pass (80%+) but exclude most route shells, all admin layout chrome, and `service.ts`** — high-value server paths can ship untested.
- **Consistency rot:** mixed `getClaims()` / `getUser()`, mixed Radix import styles (`radix-ui` umbrella vs `@radix-ui/react-checkbox`), `data-table1.tsx` naming, camelCase `useGetMessage.ts`.
- **Non-AuthError exceptions in auth forms can surface raw `Error.message`** via `extractAuthForm-error` fallback path — contradicts fallback-first auth taxonomy.
- **No `error.tsx` route boundaries anywhere** despite rules and Phase 5 error architecture shipping.
- **Knip reports four direct `@radix-ui/*` dependencies and `tailwindcss-animate` as unused** — dependency/config bloat from the fork + shadcn migration.

## Architectural mental model

Seminova is a **Next.js 16 App Router + Supabase** SaaS starter template, not a finished product. Public surface is `(marketing)/` (`/`). Auth lives under `/auth/**`. Authenticated non-admins land in `(app)/profile`. Admins use `/admin` (sidebar shell) with a real users table backed by Supabase Auth Admin API via secret-key server actions.

Session refresh and coarse route protection run in `proxy.ts` → `src/supabase/proxy.ts` (`getClaims()`, public `/` + `/auth/**` only). Admin routes get a second gate in `AdminAuthGate`. Data mutations use server actions with zod validation at the boundary; client tables use manual `useState` + `useTransition` rather than TanStack Query (except the leftover demo hook).

The design-system layer is mature: semantic tokens in `globals.css`, shadcn primitives in `src/components/ui/`, canonical patterns for errors (`InlineError` / `ErrorPanel`), toasts, data tables, and profile blur-save forms. Agent workflow docs (`AGENTS.md`, `.cursor/rules/`, skills) are a first-class product surface. Churn in the last six months concentrated on Phase 4–7 feature work (landing, admin polish, profiles, security) plus a large docs-restructure pass — application `src/` is ~11.6k LOC TypeScript, still small enough for a single-repo audit.

## Things that look bad but are actually fine

- **`src/components/ui/sidebar.tsx` (726 LOC)** — Wide shadcn install with a single exported sidebar system; deep module hiding Radix/cookie/mobile behavior. Not a god file by the repo's depth definition.
- **`profile-settings-form.tsx` (320 LOC)** — Single exported form orchestrating blur-save; helpers are co-located subcomponents. Legitimate deep module for the forms.mdc reference implementation.
- **Double admin protection (`proxy.ts` + `AdminAuthGate`)** — Belt-and-suspenders: proxy blocks non-admins early; gate ensures shell never renders without session. Reasonable for a security-sensitive template.
- **`getClaims()` in proxy vs `getUser()` elsewhere** — Supabase explicitly warns against code between client creation and `getClaims()` in middleware/proxy; other server paths correctly use `getUser()` for fresh user records.
- **`APP_HOME === PROFILE_PATH`** — Documented in `app-paths.ts` with upgrade notes for when a product adds a separate app home.
- **No `loading.tsx` files** — Route groups use Suspense fallbacks (`ProfilePageSkeleton`, `AdminShellSkeleton`) instead; valid App Router pattern.
- **Broad vitest exclusions for `page.tsx` / `layout.tsx`** — Intentional per `testing.mdc` to avoid testing shells; tradeoff is acknowledged, not accidental neglect.
- **Manual `users-table` fetching** — Server actions + `useTransition` is a legitimate pattern for admin tables; abstracting to React Query before a second table would be premature (F040).
- **`hasEnvVars` proxy bypass** — Lets clones render marketing pages before Supabase is configured; onboarding affordance, not a production security hole (production must have env vars).
