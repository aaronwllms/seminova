# RESEARCH-0001: Cursor ignore files

**Archived:** 2026-07-08

**Researched:** 2026-07-08

**Type:** technical

## Question

Should Seminova adopt `.cursorignore` and/or `.cursorindexingignore`? If yes, what belongs in a minimal, documented baseline — especially for template spinoffs?

## Scope and constraints

**In scope:** Cursor's two ignore mechanisms, what Seminova already excludes via `.gitignore` and Cursor defaults, noise candidates in this repo (archived plans, audit artifacts, frozen docs), security implications, and template portability (`initialize-project`).

**Out of scope:** Global Cursor user-settings ignore patterns (per-developer), monorepo-specific layouts, enforcing ignore policy in CI.

## Findings

### Two mechanisms, different blast radius

| File | Indexing | Agent / Tab / Inline Edit | @-mention / drag-in | Terminal & MCP tools |
| ---- | -------- | ------------------------- | ------------------- | -------------------- |
| `.cursorignore` | Blocked | Blocked | Blocked | **Not blocked** |
| `.cursorindexingignore` | Blocked | Accessible | Accessible | Accessible |

Source: [Cursor ignore-file reference](https://cursor.com/docs/reference/ignore-file).

**Implication:** `.cursorignore` is a hard gate — a mis-pattern can hide rules, skills, or types agents need and they cannot recover via @-mention. `.cursorindexingignore` only reduces @Codebase noise; agents can still read excluded paths when relevant.

### What is already excluded without extra files

**`.gitignore`** covers the heavy paths: `node_modules`, `.next`, `coverage`, `.env*.local`, lockfile-adjacent paths, build output, etc.

**Cursor default indexing exclusions** (applied even without ignore files) add a long list on top of `.gitignore`: lockfiles, `node_modules`, `.next`, binaries, media, fonts (`*.ttf`, `*.woff`, …), `*.svg`, `.env*`, and more. See the full list in the [official docs](https://cursor.com/docs/reference/ignore-file#default-ignore-list).

**Net:** For a repo this size, the default stack already excludes virtually all bytes that would matter for performance.

### Noise candidates (if @Codebase quality degrades later)

These are the main *content* paths that could pollute semantic search without affecting build performance:

1. **`.cursor/plans/archive/`** — completed epic plans; useful on demand via `/archive-cursor-plans`, rarely needed in automatic retrieval. Largest single noise source (~60 files).
2. **`docs/archive/`** and **`docs/prds/archive/`** — frozen history; small today (~20 KB each) but grow per shipped phase.
3. **Root audit artifacts** (`TECH_DEBT_AUDIT.md`, `TEST_AUDIT.md`, `RULE_AUDIT.md`, `SECURITY_AUDIT.md`) — regenerated by audit skills; can surface stale findings in @Codebase. Still useful when @-mentioned during an audit.

Paths agents must **not** hard-block: `.cursor/rules/`, `.cursor/skills/`, active `.cursor/plans/*.plan.md`, `AGENTS.md`, `src/types/database.types.ts`, active PRDs.

### Security note

Cursor recommends global user ignore patterns for secrets (`.env*`, credentials, keys). The default indexing list already includes `.env*`, which excludes env files from the index only — **not** from Agent, Tab, or @-mentions. Hard-blocking secrets requires `.cursorignore`; use `!.env.example` so the committed placeholder file stays accessible.

**`.cursorignore` is not a security boundary:** Agent terminal and MCP tools can still reach ignored paths. Treat `.gitignore` + secret hygiene as the real control; ignore files are indexing/access hygiene, not vaults.

### Template spinoff angle

`initialize-project` already purges Seminova-specific history (`plans/archive/`, `docs/archive/`, active and archived `RESEARCH-*.md`, backlog entries). A committed ignore baseline would mainly help **forks that accumulate their own** archive noise over time — not Seminova's current indexing performance.

If a baseline is adopted, it should ship with the template, be documented in `.cursor/README.md`, use **soft** indexing exclusions for archives, and a **minimal hard** `.cursorignore` for secrets only.

## Options compared

| Option | Pros | Cons |
| ------ | ---- | ---- |
| **A — No ignore files** (status quo) | Zero misconfiguration risk; defaults already cover bytes; matches current repo size | No proactive @Codebase noise control for archives; spinoffs start with no documented policy |
| **B — Refined (implemented)** | `.cursorindexingignore` for archives + minimal `.cursorignore` for secrets | Best of both: @Codebase noise control without blocking agent reads of history; hard block on env/keys with `!.env.example` | Two files to maintain; `.cursorignore` still does not block terminal/MCP |
| **C — `.cursorignore` for archives** | Strongest exclusion on history | High foot-gun risk on `.cursor/` and types; blocks @-mention recovery for archived plans |
| **D — `.cursorignore` for everything** | Maximum control | Combines C's risks with little added value for this repo |

## Recommendation

**Implemented 2026-07-08: Refined Option B** — two repo-root files with split responsibilities:

**`.cursorindexingignore`** (soft — archives only):

```sh
.cursor/plans/archive/
docs/archive/
docs/prds/archive/
docs/research/archive/
```

**`.cursorignore`** (hard — secrets only; patterns aligned with [Cursor's global-ignore guidance](https://cursor.com/docs/reference/ignore-file#global-ignore-files)):

```sh
**/.env
**/.env.*
!.env.example
**/credentials.json
**/secrets.json
**/*.key
**/*.pem
**/id_rsa
```

Documented in [`.cursor/README.md`](../../../.cursor/README.md). Workflow backlog item removed.

Do **not** expand `.cursorignore` to archives, `.cursor/rules/`, `.cursor/skills/`, or `src/types/database.types.ts`.

**Performance note:** At ~3 MB tracked, indexing performance was not the driver — template portability, @Codebase noise control, and secret hard-blocking were.
